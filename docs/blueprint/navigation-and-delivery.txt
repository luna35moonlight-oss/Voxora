19. Build order: From today's code to a real downloadable app
A project this large needs a controlled sequence. Otherwise we'll have 40 flashy screens and an AI buddy that can't remember yesterday.

Phase 0: Preserve and audit

Phase 1: Alpha's independent brain
Build accounts, buddy identity, personality profiles, non-mirroring conversation rules, memory, AI routing, text conversation and permission management.




Phase 2: Live conversation
Add streaming speech, interruptible dialogue, transcription, voice customisation, notifications and background behaviour within platform limits.




Phase 3: Independent mobile app
Deliver working Android builds with authentication, local data, offline capability, task reminders and validated online syncing.




Phase 4: Work and life tools
Calendar integrations, documents, meetings, research, approved email actions, coding assistance and workflow automation.

The phases can overlap where sensible, but each production feature should pass actual tests before being labelled complete.

20. The non-negotiable rules for our developers and Codex
These should govern every future implementation:
1. Audit before editing. Never replace or destroy working functionality without inspecting the existing code and data.
2. No fake buttons. Every visible action must work, clearly say it's unavailable, or be absent from production.
3. No invented success. Sending, saving, syncing, exporting and generating must be verified.
4. No silent AI changes. Preserve uploaded originals and make creative transformations reversible where feasible.
5. No automatic agreement. The buddy should remain truthful and able to challenge assumptions.
6. No unauthorised external actions. Deleting, paying, sending, publishing and sharing require appropriate user permissions and confirmations.
7. No uncontrolled memory collection. Personal information remains under user control.
8. No model lock-in. The AI router must support replacing providers.
9. No browser-only dependency. Core app experiences must have native or otherwise genuine installable implementations.
10. No untested production claims. Automated and manual verification must be recorded.
11. No forgotten work. Maintain a feature register with implementation status, blockers, tests and release history.
12. No needless duplication. Use shared modules and consistent APIs across mobile, web and desktop.
